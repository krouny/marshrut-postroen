# Маршрут Построен — навигация по проекту

Читай этот файл в начале каждой сессии.

## Что это за проект

**Маршрут Построен** («Сис & Сис») — веб-сайт для планирования путешествий:
поиск направлений с готовыми параметрами (даты, гости) в ссылках партнёров,
ИИ-планировщик поездки по дням, совместные поездки с чатом и общими файлами.

Freemium: бесплатно навсегда (поиск, сохранение, совместные поездки, чат),
Путешественник 100 руб/мес (+ ИИ-планировщик), Премиум 500 руб/мес (+
персональный план). Оплата пока ручная (код активации через Telegram) —
автооплата не подключена, см. `.business/company/legal.md`.

Начинался как студенческий портфолио-проект (запуск 26 июля 2026), сейчас
растёт как реальный продукт — см. `.business/company/about.md` для контекста,
почему цели скромные, а не как у финансируемого стартапа.

Подробности — в `.business/INDEX.md`.

> экономика/цели не должны быть публичными по умолчанию.

## Ключевые принципы

1. Один клик к результату — параметры один раз, дальше подставляются везде.
2. Freemium — бесплатные функции навсегда, платные расширяют, не блокируют
   базовую пользу.
3. Не обещать то, чего не построено (сейчас: автооплата, реальные цены в
   карточках, реферальная программа) — ни в текстах, ни в соцсетях.
4. Не выдумывать цифры — статистика в кабинете и рейтинг считаются из
   реальных действий пользователя, не из демо-данных.
5. Конкуренты реальны (Wanderlog, Layla, Trip.com и другие) — не писать
   «мы единственные». Честное отличие — заточка под русскоязычного
   пользователя и партнёров, доступных из РФ.

## Стек

Vanilla JS (без фреймворков), HTML/CSS, один файл `index.html` — сознательное
решение: деплой перетаскиванием на Netlify, без сборщика и DevOps.
Backend: Supabase (PostgreSQL, Auth, Realtime, Storage), Row Level Security.
Карты: Leaflet. Внешние API: Wikipedia REST/Action API, OpenStreetMap
Nominatim (геокодинг), open.er-api.com (курсы валют).
Хостинг: Netlify. Код: GitHub (публичный, портфолио).

## Как работать с проектом

- Перед задачей читай этот файл + нужные файлы из `.business/`.
- Меняется бизнес-логика или добавляется функция — обновляй `.business/INDEX.md`
  и соответствующий файл, особенно `products/product-1.md` (список
  реализованного/нереализованного).
- Прежде чем писать на сайт или в соцсети цифру/заявление о конкурентах —
  проверь, подтверждено ли оно (принцип 5 выше).

## ВАЖНО: завершение каждой сессии

Рефлексия в `.business/история/YYYY-MM-DD-название.md`:

1. Какая задача была поставлена.
2. Как решал.
3. Решил — да / нет / частично.
4. Что можно было лучше.
5. Как было → как стало.

## Безопасность

- Никогда `rm -rf` без явного подтверждения
- Никогда `git add -A` — только свои изменения
- Ключи Supabase в коде — это ожидаемо (публичный anon key, защита через RLS
  на стороне базы), но никогда не коммить service_role ключ или пароли
